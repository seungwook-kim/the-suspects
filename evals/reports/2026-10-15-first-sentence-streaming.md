# 첫 문장부터 보여 주기 (2026-10-15)

응답 속도 개선 5단계. 기준선은 [2026-10-14 응답 지연 기준선](2026-10-14-response-latency.md).

## 목적
PRD §14.1 "첫 글자부터 스트리밍"과 §14.1 지연 예산(인물 답 첫 토큰 1.5초)을 향해, 직접 쓴 질문·증거 제시처럼
미리 만들 수 없는 답도 기다리는 시간을 줄인다. 단, PRD §7.2 게임 마스터 검사(보여 주기 전에 검사)는 지킨다.

## 설계: 문장 단위로 검사하고 내보내기
- 모델이 답(JSON)을 쓰는 동안 끝난 문장이 생길 때마다, 지금까지의 글 전체를 게임 마스터 코드 검사(1단계)에 넣는다.
  - 통과하면 그 문장을 바로 화면으로 보낸다.
  - 걸리면 거기서 끊는다. 이미 보여 준 문장까지가 답이 되고, 남은 생성은 받지 않는다.
  - 한 문장도 못 보여 줬으면 평소 경로(다시 만들기 최대 2번 → 성격별 기본 대사)로 간다.
  - LLM 검사(2단계)가 필요한 문장이 나오면 거기서 멈췄다가, 다 쓴 뒤 그 검사가 통과하면 나머지를 보낸다.
  - 세 문장을 넘으면 거기서 끊는다. 수첩에 남는 진술은 화면에 나간 글과 똑같다.
- 출력 형식에서 표정을 대사보다 먼저 쓰게 해(NPCReply 필드 순서) 표정이 첫 문장보다 먼저 바뀐다.
- 서버는 행동 처리 중 이벤트를 만드는 즉시 내보낸다(전에는 행동이 다 끝난 뒤 한꺼번에).
- 증거 제시·블러핑 반응도 같은 경로. 미리 만든 칩 답은 이미 다 있으므로 그대로 보낸다.
- 설정 `speed.stream_npc_answers`(기본 켬)로 끌 수 있다. 실시간 출력이 없는 연결(가짜 LLM 등)은 저절로 평소 경로.
- 코드: `server/agents/npc.py` `answer_stream`, `server/llm/client.py` `structured_stream`, `server/llm/partial_json.py`,
  `server/llm/cli_provider.py` `stream_cli`, `server/game/service.py` `act`(즉시 내보내기).

## 다시 돌리는 법
```
uv run python -m server.llm.latency --stream-check 3   # 끔/켬 번갈아 3번씩 (진짜 모델 사용량이 든다)
```
임시 폴더에 새 판을 만들고(그림 끔) 처음 장소의 첫 인물에게 "어젯밤 사건 시각쯤 어디 계셨어요?"를 직접 쓴다.
첫 대사 조각 = 행동을 보낸 뒤 첫 `TEXT_MESSAGE_CONTENT`가 나오기까지(서버 안, 화면 연출 제외).

## 결과
환경: 개발 PC, 개발용 프로필 `dev`(명령줄 도구, 같은 모델, 질문마다 프로그램 시동 2~3초 포함).

| 방식 | 횟수 | 첫 대사 조각 p50 | 첫 대사 최대 | 행동 끝 p50 |
|:--|--:|--:|--:|--:|
| 다 만든 뒤 보여 줌(전) | 3 | 3.9초 | 4.9초 | 3.9초 |
| 첫 문장부터 보여 줌(후) | 3 | 2.0초 | 2.3초 | 3.7초 |

HTTP로 받은 이벤트 시각(임시 서버, 직접 쓴 질문 1번):

| 시각 | 이벤트 |
|--:|:--|
| 0.02초 | 행동 시작 |
| 2.34초 | 표정(emotion) |
| 2.35초 | 첫 두 문장 |
| 3.15초 | 셋째 문장 |
| 4.48초 | 대사 끝, 수첩·상태 변화분, 행동 끝 |

브라우저 화면(임시 서버·임시 화면, 1440×900, 직접 쓴 질문 1번, 답 글자를 50ms마다 기록):
- 0.05초에 기다림 표시 "…", **2.03초에 첫 글자**, 이후 한 글자씩 찍혀 3.35초에 대사가 다 보였다.
- 표정 칸이 "긴장"으로 바뀌고 수첩 진술 수가 1이 됐다. 오류 없음. 사용자 게임 기록과 그림 사용량에는 영향 없음.

## 해석
- 첫 대사가 화면에 나오는 시간이 절반 가까이 줄었다(3.9 → 2.0초). 전체 시간은 그대로다(모델이 쓰는 양은 같음).
- 개발용 연결은 질문마다 프로그램 시동 2~3초가 앞에 붙는다. 출시용 API 연결에서는 이 시간이 없어
  첫 문장은 더 빨라질 것으로 보지만, API로는 아직 재지 않았다(API 키를 쓰지 않기로 한 결정, 2026-10-14).
- 마지막 문장 뒤 약 1.3초는 모델이 근거 id(used_ids)를 마저 쓰고 프로그램이 끝나는 시간이다. 화면에는 글이 이미 다 나와 있다.

## 한계
- 표본이 적다(방식마다 3번, HTTP 1번). 같은 질문 하나.
- 문장 단위라 첫 문장이 길면 그만큼 늦게 나온다(글자 단위보다 느림). 검사 없이 글자를 흘리지 않기 위한 선택이다.
- 걸리는 문장에서 끊으면 답이 짧아진다. 끊긴 비율을 호출 기록(extra.stopped)으로 따로 봐야 한다.
- 명령줄 연결의 실시간 출력은 출력 형식 강제 인자 없이 지시문의 JSON 안내로만 받는다. 형식이 틀리면 보여 준 문장까지만 쓴다.
