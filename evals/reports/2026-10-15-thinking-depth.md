# 역할별 생각(추론) 깊이 설정 (2026-10-15)

응답 속도 개선 4단계. 기준선은 [2026-10-14 응답 지연 기준선](2026-10-14-response-latency.md).

## 목적
기준선에서 긴 답이 느린 주원인으로 생각 토큰을 꼽았다(긴 답 출력 796 → 생각 끔 329토큰, 9.9 → 5.5초).
개발 PC 전용 꼼수가 아니라, 개발(명령줄)·출시(API) 어느 연결에서든 같은 설정으로 생각을 끌 수 있게 만들고,
인물 답에 실제로 적용할지 속도와 답 내용으로 판단한다.

## 만든 것
- 역할 설정에 `thinking: off`를 적으면 생각을 끈다(`server/llm/client.py`).
- 끄는 방법은 연결(프로필)마다 `thinking_off`에 적는다. API는 요청에 더할 값(`extra_body`), 명령줄은 환경 변수(`env`).
  공급자마다 값이 달라 실제 값은 커밋하지 않는 `config/models.local.yaml`에만 둔다. 끄는 방법이 없는 프로필은 그대로다.
- 지연 측정 도구에 `--thinking off`를 더했고, 다시 받은 답 글도 표에 함께 낸다(속도와 품질을 같이 보려고).

## 방법
```
uv run python -m server.llm.latency --since "2026-10-14 13:40" --until "2026-10-14 13:59" --replay 4 --roles npc
uv run python -m server.llm.latency --since "2026-10-14 13:40" --until "2026-10-14 13:59" --replay 4 --roles npc --thinking off
```
2026-10-14 실제 플레이의 인물 답 요청 4개를 같은 개발용 연결로 생각 켬(기본)·끔 한 번씩 다시 보냈다.

## 결과
| 요청 | 기록(10-14) | 생각 켬 | 생각 끔 |
|:--|:--|:--|:--|
| 1 (긴 답) | 8.3초, 708토큰 | 4.8초, 253토큰 | 5.0초, 328토큰 |
| 2 (긴 답) | 8.1초, 427토큰 | 5.1초, 184토큰 | 6.0초, 245토큰 |
| 3 | 5.4초, 194토큰 | 4.7초, 196토큰 | 4.2초, 197토큰 |
| 4 | 5.6초, 164토큰 | 3.7초, 157토큰 | 3.9초, 179토큰 |

답 내용(요약):
- 생각 끔은 묻지 않은 정보를 더 붙였다. 요청 1은 "11시 55분쯤 다시 올라왔다"를 덧붙였고, 요청 2는 "11시 43분에 지하 복도를 나왔다"는 구체적인 시각을 먼저 말했다.
- 생각 켬은 같은 질문에 더 짧게 답하고 되묻기로 끝냈다("그건 왜 물으신대유?").
- 말투(사투리·존댓말)는 둘 다 유지했다.

## 해석과 결정
- 이번 측정에서는 생각을 켠 쪽도 생각을 적게 써서(출력 157~253토큰) 속도 차이가 거의 없었다. 어제 기준선(796토큰)과 달리, 생각 양이 호출마다 크게 흔들린다.
- 생각을 끄면 인물이 정보를 먼저 늘어놓는 경향이 보였다. 단서를 아껴서 흘려야 하는 이 게임에서는 품질 손해다.
- 결정: 끄는 설정은 만들어 두되, 인물 답(npc 계열)에는 적용하지 않는다. 개발용 연결의 모든 역할이 지금은 기본값(생각 켬)이다.

## 한계
- 요청 4개, 방식마다 한 번씩이다. 생각 양이 호출마다 흔들려 속도 비교는 결론을 낼 수 없다.
- 품질은 사람이 답 4쌍을 읽고 본 것이다. PRD §17의 G-Eval(캐릭터 일관성·정보 누출)로 다시 재야 한다.
